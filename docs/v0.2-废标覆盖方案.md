### 2. 归纳为 32 条具体可核对的废标原因

按"评标专家实际翻标书时在核对什么"归类，去掉纯操作类（上传超时、解密失败）和纯平台类（信用分、四库一平台查询），保留能在投标文件本身看到的项。

**A. 资格类（12 条）**
A1 资质等级/专业不符　A2 安全生产许可证过期　A3 营业执照过期或名称与投标人不一致　A4 项目负责人建造师等级/专业不符　A5 项目负责人安 B 证过期或缺失　A6 项目负责人注册单位非投标人（挂靠）　A7 现场管理人员岗位/人数不足、一人多岗　A8 八大员岗位证书与岗位不匹配（安全员无 C 证）　A9 类似工程业绩数量不够、竣工日期不在年限内、证明材料残缺　A10 社保证明月份不在要求区间、单位不是投标人、人名对不上　A11 承诺函缺失（无行贿犯罪、项目负责人承诺、诚信承诺）　A12 联合体不允许或协议缺失

**B. 商务类（10 条）**
B1 总价高于控制价　B2 大小写、封面、汇总表金额不一致　B3 工期超要求　B4 质量标准低于要求　B5 投标有效期不足　B6 保证金金额/账户/时间不符　B7 附加招标人不能接受的条件（附录偏离）　B8 未按招标格式填写附录/表单缺失　B9 清单缺项、未报价、算术错误、安全文明费低于规定　B10 同一项目多个报价

**C. 签署与日期类（5 条）**
C1 投标函、承诺函等未签字盖章　C2 签署日期晚于投标截止或明显错误（年份没改、2 月 30 日）　C3 授权委托书有效期未覆盖评标期、生效日晚于截止日、委托人不是法定代表人　C4 法定代表人/委托代理人身份证过期　C5 各表单日期彼此矛盾（承诺函早于授权书）

**D. 技术类（3 条）**
D1 暗标出现投标人名称、人名、印章　D2 其他项目内容粘贴残留（项目名称、编号、工程类型不符）　D3 ★参数负偏离、危大清单与数据表不对应

**E. 单份文件查不到的（2 条，明确不做）**
E1 串标特征：MAC、IP、CA 归属、保证金转出账户与他人相同、内部识别码相同　E2 低于成本价、信用中国/黑名单/安全标准化 D 级、四库一平台业绩核验

## 三、新增与升级规则清单

原则：每条规则只读已经解析好的结构，不新增大模型规则；OCR 只加 4 到 9 页且复用已有页。规则 ID 延续现有分组。

### 第一批：0 token，纯文字层（约 1.5 天）

**P-09 签署日期**（严重度 major，supersedes 无）
- 数据：投标函日期（已有）、法定代表人资格证明书落款、投标函附录落款、诚信/履约/农民工/建机一体化承诺函落款、定标文件承诺函落款。统一用 `_DATE_RE` 取每张表单文字层最后一个日期。
- 招标侧新增 `HardValues.notice_date`：第 1 章招标公告落款日期或前附表「疑问截止时间」前推，取不到则只做上限判断。
- 判定：任一日期 > 投标截止日 → fail；任一日期 < 招标公告日 → fail；日期不合法（2 月 30 日、年份与截止日差 ≥ 1 年）→ fail；各表单日期跨度 > 30 天 → warning；一张表单没有日期 → 不判（平台生成表单日期常在签章图片里）。
- 证据：每个日期一条 Location。

**S-03 岗位证书与岗位匹配**（reject，source_clause 3.1.8）
- 数据：`Person.cert`（人员表第三部分「岗位证书类型」列）。
- 判定：安全员的证书须含「C」；其余岗位证书类型须包含岗位名去掉「土建/设备安装」后的词（施工员↔施工员）；证书编号为空 → warning。人员表未解析出证书列 → manual。
- 解析改动：`_parse_staff_table_text` 把姓名后第 2 行作为 `cert_no`（现在只取第 1 行为 `cert`）。

**S-05 建造师注册专业与招标要求一致**（reject，3.1.8）
- 数据：`hard.pm_requirement` 里的「XX工程专业」；人员表第一部分「注册专业」列或简要情况表「建造师专业」。
- 判定：招标写了专业且投标专业不含该词 → fail；招标未限定专业 → na。
- 解析改动：`Person.reg_major` 新字段，人员表第一部分「注册专业」取值；`_enrich_from_form` 增加 `kv.get("建造师专业")`。

**P-07 升级：建造师注册证书有效期（文字层）**
- 简要情况表文字层「建造师注册证书使用有效期(若有) 2026.7.30-2027.1.26」→ 止日 < 截止日 → fail；止日 < 截止日 + 投标有效期 → warning「有效期内可能失效，评标可能质疑」。没这一行 → 走原逻辑。

**S-07 人员表自身校验**（major）
- 人员表「查询有效期 2026-08-12至2027-02-08」须覆盖截止日；表头「招标项目编号」须等于 `req.project_code`；否则 fail（用错项目的人员表是真实事故类型）。
- 身份证：简要情况表身份证号做校验位检查（错 → warning「身份证号录入错误」）；按截止日算年龄，≥ 60 → warning「已达退休年龄，评标可能质疑到岗」。资格证明书里法定代表人身份证同样处理。

**X-07 异项目编号残留**（major，0 token）
- 全文扫描 `E\d{16,19}` 及「招标项目编号」后面的串，凡不等于本项目编号（及标段编号前缀）的，按页列出，最多 5 处 → warning「疑似其他项目内容残留」。技术文件段也扫（暗标里出现别的编号同样致命）。补充扫描其他项目名称：取全文出现 ≥ 2 次且含「工程/项目」的 8 到 30 字串，与本项目名称相似度 < 0.5 的列出，作为 info。

**Q-09 升级：业绩数量与年限（文字层）**
- 招标侧：数据表 3.1.9 解析「前 N 年内」→ `hard.similar_projects_years`；「以竣工验收日期为准」标志。
- 投标侧：类似工程业绩汇总表（资格文件与定标文件各一份）用 `tables_for_pages` 读首页表格，每行取项目名称、合同金额、竣工验收日期（表头含「竣工」「验收」「日期」的列）。文字层被切碎时退化为整页正则找日期。
- 判定：合格行数（竣工日期 ≥ 公告日 − N 年）< 要求数 → fail；日期读不出 → manual 并列出行数。证明材料扫描件不 OCR，仍留人工核对「合同+验收证明齐全」。

### 第二批：复用/少量新增 OCR 页（约 1.5 天，需 key 有效）

**OCR 提示词改一次，版本号 1 → 2**（会使旧缓存失效，一次性）
- `cert` 提示词增加两个字段：`落款/签发日期`、`缴费月份或期间`；类型列表里明确列出「授权委托书、身份证、社保缴费证明、保函」。字段格式不变，仍一行一项。

**C-07 授权委托书与法定代表人身份证**（reject，3.1.10 / 第 8 章格式）
- 页：法定代表人资格证明书表单的扫描页（黄金样本 p13-17，Q-02 已经 OCR，**0 新增页**）。
- 判定：
  - 投标函签字人 == 法定代表人（`idx.legal_rep`）→ 授权委托书不适用，只查身份证：OCR 行类型含「身份证」→ 有效期止 ≥ 截止日，否则 fail；读不到 → warning。
  - 签字人 ≠ 法定代表人 → 必须有授权委托书行：委托人含法定代表人姓名、被委托人含签字人姓名、签发日期 ≤ 截止日、有效期止 ≥ 截止日 + 投标有效期天数（读不到止日期但写「至本项目结束」类字样 → pass）。

**C-05 升级：安全员社保逐人核对**（reject，3.1.8）
- 页：「拟派出的安全员及其社保凭证」表单扫描页，最多 3 页（黄金样本 p44-46）。
- 判定：OCR 行里人名 == 人员表安全员姓名（否则 fail「社保证明人名与人员表不符」）；单位含投标人名称（否则 fail）；缴费月份 ≥ 截止日前 N 个月（N 取数据表 3.1.8 或第 8 章说明里的「近 N 个月」，取不到默认 3，只做 warning）。

**GC-T-03 升级（磋商模板）：养老保险逐人**
- 页：全文文字层含「养老保险」的页各取 1 页，按人员表人数封顶 8 页。
- 判定：OCR 出的人名集合 ⊇ 项目团队人名集合，否则列出缺的人 → fail；月份在「截止前六个月内任一月」→ 否则 warning。

**C-06 升级：保证金凭证三要素**
- 同一批 OCR 页，0 新增。
- 增判：凭证里出现的付款账号须等于「投标人基本账户信息」表（文字层）里的账号，不等 → fail「非基本账户转出」；凭证文字含本项目招标编号，否 → warning；保函类：有效期止 ≥ 截止日 + 有效期天数 + 30 天，否 → fail。

**GC-Q-01 升级（磋商模板）：财务状况报告年份**
- 页：附件 3-4-2 首页 1 页。判定：OCR 到的年份 ≥ 截止年份 − 1（上一年度审计报告）否则 warning。

### 第三批：先做可行性验证再决定（可选）

**D-07 已标价清单未报价项**（reject，7.1）
- 数据：清单页 p60-842 文字层。逐页正则匹配「项目编码 12 位 + 项目名称 + 单位 + 数量 + 综合单价 + 合价」行，综合单价为空或 0 且数量 > 0 的行列出。

- 不 OCR、不调模型，只吃 CPU（约 800 页 × 正则，预计 < 5 秒）。

## 四、成本控制：每次检查的 token 预算

### 现状（施工标，黄金样本量级 1000 页）

| 项 | 用量 | 估算 token |
|---|---|---|
| 视觉 OCR | 上限 40 页，实际约 20 页（Q-02 六页 + 三证 + 简要情况表 + 保证金 + 安全员社保） | 每页约 1.5k 图片 + 0.7k 输出 ≈ 2.2k → **约 45k** |
| 大模型窗口 | Q-16 1 次、B-09 1 次、B-10 最多 8 次、T-03 最多 7 次；上限 25 次 | 每次约 4.5k → **典型 50k，最坏 110k** |
| 确定性规则 | 0 | 0 |

磋商模板没有大模型规则，只有 OCR。

### 方案后

| 项 | 变化 | 备注 |
|---|---|---|
| 第一批 7 条规则 | +0 | 全部文字层 |
| C-07、C-06 升级 | +0 页 | 复用 Q-02 与保证金已 OCR 页 |
| C-05 升级 | +0 到 3 页 | 这几页现在也在 OCR 清单里，只是没解析 |
| GC-T-03 升级 | +最多 8 页 | 仅磋商模板 |
| GC-Q-01 升级 | +1 页 | 仅磋商模板 |
| 大模型 | +0 次 | 不加新的 L 规则 |

单次检查增加量：施工标 **≈ 0**，磋商 **≤ 9 页 ≈ 20k**。

### 顺手压成本的三处

1. **OCR 页优先级**：`prefill_ocr` 现在按规则顺序收集页、超预算截尾。改为按 (规则严重度, 表单) 排序，reject 级证书页先做，业绩类扫描页最后做，超预算时先丢业绩页而不是丢安许证页。
2. **大模型调用上限从 25 降到 16**：B-10 最多 5 条、T-03 最多 5 段。最坏情况 110k → 70k。这两条规则的后几段命中率很低。
3. **判定结果缓存**：以 (招标 hash, 投标 hash, 规则 id, 提示词版本) 为键缓存 LLM 判定，重复检查同一对文件时 0 token。用户改标书重导出后 hash 变化会自然失效，不会用旧结果。

DPI 保持 110 不再降；降到 90 会让证书编号识别错。

## 七、明确不做的事

- 串标特征（MAC、IP、CA、账户同名、识别码）：单份文件无法判定，保持 Q-14 人工提示。
- 信用中国、黑名单、安全标准化等级、四库一平台业绩核验：需要联网查政府平台，工具定位是离线检查。
- 签字盖章有无：电子标以 CA 签章为准，PDF 文字层无法判断，保持 E-02 人工提示。
- 排版、字体、行距类格式要求：福建平台生成的文件格式固定，不是废标主因。
- 低于成本价判定：没有可靠算法，评标也是先要求说明再判。
